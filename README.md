# jobbytime-ai-review

AI-ревьюер merge request'ов для репозиториев группы Jobbytime.

## Как подключить

В `.gitlab-ci.yml` целевого репозитория:

```yaml
include:
  - project: jobbytime.com-group/jobbytime-ai-review
    ref: v1
    file: templates/ai-review.yml
    inputs:
      allow_failure: false  # боевой режим: открытое замечание держит мердж
```

`allow_failure: true` — shadow-режим для обкатки в новом репозитории. Держать его
дольше обкатки не стоит: джоба, которая падает и никого не останавливает, читается
как «пайплайн прошёл с предупреждениями» и перестаёт восприниматься вообще.

Сам `jobbytime-ai-review` с 2026-08-17 ревьюит себя в боевом режиме. Инструмент,
который блокирует чужие merge request'ы, а свои пропускает по предупреждению,
заслуживает меньше доверия, чем просит.

> [!note] В этом репозитории джоба ревьюит ветку, а не выпущенный образ
> `python -m reviewer` запускается из каталога с проверяемым репозиторием, и его
> собственный пакет `reviewer/` перекрывает установленный в образе. В подключающих
> репозиториях каталога `reviewer/` нет, поэтому там работает код образа.
>
> Отсюда же выход из тупика «ревьюер сломан и не пропускает собственное
> исправление»: в MR с исправлением временно поставить `allow_failure: true` и
> вернуть обратно в том же MR. Это видимое и обсуждаемое действие, в отличие от
> постоянного исключения, которого не видно.

Нужные переменные CI (уровень группы, Masked, без Protected):

- `OPENAI_API_KEY`
- `AI_REVIEW_GITLAB_TOKEN`
- `ANTHROPIC_API_KEY` — только пока включён Claude (см. «Переключение на Claude»)

Настройки конкретного репозитория — в файле `.ai-review.yml` в его корне.

Детерминированный слой ревьюера — только `gitleaks`. Линтеры (`golangci-lint`,
`eslint`, `ruff`, `shellcheck` и т. п.) сюда не входят: у линтера в native CI-job
самого репозитория всегда правильный тулчейн (те же плагины и конфиг, что уже
стоят в репозитории), тогда как обобщённый линтер в образе ревьюера рисковал бы
разойтись с ними. Линтинг — отдельный job в пайплайне репозитория, до `ai-review`.

Поля `model` и `model_high_risk` **обязательны** и должны быть заданы явно в
`.ai-review.yml` каждого репозитория — у шаблона `templates/ai-review.yml` нет
дефолтного значения модели. Пустой или отсутствующий `model` (в том числе
отсутствие самого файла `.ai-review.yml`) приводит к `ConfigError` и коду
выхода 2 (техническая ошибка) ещё до похода в OpenAI.

## Переключение на Claude

Провайдер выбирается переменной CI, а не `.ai-review.yml`: одна переменная на
группе GitLab переводит все репозитории сразу и так же возвращает обратно, без
merge request в каждый репозиторий.

| Переменная (группа, Masked, без Protected) | Значение |
|---|---|
| `AI_REVIEW_PROVIDER` | `anthropic` — ревью на Claude; пусто или нет — как в `.ai-review.yml` |
| `ANTHROPIC_API_KEY` | ключ из Claude Console |
| `AI_REVIEW_MODEL`, `AI_REVIEW_MODEL_HIGH_RISK` | необязательно; по умолчанию `claude-sonnet-5-5` и `claude-opus-5-5` |

Protected ставить нельзя: такие переменные видны только на защищённых ветках, а
ревью идёт в пайплайнах merge request на обычных.

Что при этом остаётся как в репозитории: пути, лимиты, `high_risk_paths` —
меняются только модели. Цены моделей Claude встроены в ревьюер
(`reviewer/config.py`, `BUILTIN_PRICING`), строка стоимости считается без
правки `.ai-review.yml`.

**Откат на OpenAI внутри прогона.** Если Claude недоступен — кончились
кредиты, ключ истёк или отозван, сеть, перегрузка после ретраев SDK, — прогон
продолжается на OpenAI-моделях из `.ai-review.yml` (половина high-risk — на
`model_high_risk`), в логе джобы одна строка
`AI review: Claude недоступен (...), ревью продолжено на OpenAI (...)`, и до
конца прогона Claude больше не спрашивается. Красный пайплайн из-за биллинга
ревьюер не даёт: он блокирующий, и такой отказ остановил бы мерджи всей группы.
Без `OPENAI_API_KEY` откатываться некуда, и ошибка Claude даёт код 2.

**Отличия Claude, учтённые в провайдере** (`reviewer/llm/anthropic_provider.py`):

- Opus 5.5 и Sonnet 5.5 отвечают 400 на `tool_choice: any`, поэтому им
  отправляется `auto`; цикл и так напоминает модели вызвать инструмент.
- Thinking у них включён всегда, и внутри tool-use хода его блоки обязаны
  вернуться без изменений. История цикла в формате OpenAI их не хранит, поэтому
  провайдер держит блоки ответа по id вызова и подставляет обратно.
- Кеширование промпта автоматическое (`cache_control` на уровне запроса). Без
  него прогон дороже примерно вчетверо. В строке стоимости — `запись в кеш N`.
- Последний шаг цикла (бюджет шагов исчерпан) предлагает только
  `submit_findings`; смена набора инструментов сбрасывает кеш, так что этот шаг
  оплачивается полностью.

Вернуться на OpenAI — удалить или очистить `AI_REVIEW_PROVIDER`.

## Версионирование

- Точные теги (`v1.1`, `v1.2`, ...) — неизменяемы. Каждый фикс/фича идёт новым точным
  тегом, старые точные теги никогда не двигаются и не удаляются.
- `v1` — подвижный указатель на последний стабильный тег внутри первой мажорной
  версии (`v1.x`). Именно на него ссылаются `include`'ы в подключающих репозиториях
  (`ref: v1`), поэтому обновление `v1` на новый коммит — это, по сути, релиз для всех
  репозиториев группы одновременно. Двигать `v1` — осознанное решение, а не рутина:
  `git tag -f v1 <sha> && git push -f origin v1`.
- Ломающие изменения (несовместимый формат `.ai-review.yml`, смена контракта exit-кодов
  и т. п.) — новая мажорная версия, `v2`, отдельный подвижный тег. `v1` при этом не
  трогается, пока все репозитории группы не будут готовы мигрировать.

## Два списка путей: `skip_paths` и `generated_paths`

Оба перечисляют файлы, которые ревьюер не читает, но отвечают на разные вопросы,
и путать их дорого.

| | `skip_paths` | `generated_paths` |
| --- | --- | --- |
| Вопрос | стоит ли вообще запускать ревью этого merge request | нужно ли читать этот файл |
| Дифф только из них | прогон отменяется, код 0 | прогон отменяется, код 0 |
| Дифф смешанный | файлы **остаются** в диффе и попадают в промпт | файлы **уходят** из диффа |
| Считаются в лимит размера | да | нет |
| Типичное содержимое | `*.md`, лицензия, картинки | словарь, собираемый скриптом из данных в том же репозитории |

Почему `.md` из смешанного диффа не выбрасывается — решение осознанное: README
нередко и есть то место, где видно, что изменение описано неверно.

`generated_paths` заведён после замера на `jobbytime-matcher!133` (21.09.2026):
merge request со сборщиком словаря, его тестами и самим словарём был отвергнут
целиком — «изменено 8924 строк, лимит 3000», код выхода 3. Не прочитано ничего,
включая сборщик, при том что 8000 строк из 8924 были собранным файлом. Класть
сюда стоит только то, про что в репозитории есть тест «файл равен тому, что
выдаёт сборщик»: без такого теста файл перестаёт читать и человек, и ревьюер.

В лог попадают оба списка: файлы называются поимённо, а не исчезают молча.

## Коды выхода

| Код | Значение |
| --- | --- |
| 0 | замечаний нет, merge не блокируется |
| 1 | есть открытые замечания |
| 2 | техническая ошибка, нужен реран |
| 3 | merge request слишком большой, надо разбить |
